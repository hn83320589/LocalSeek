## 5. 補充說明

### 第二次量測（新行程，沿用同一份索引，`--skip-build`）

查詢延遲有明顯的起伏，所以兩次都列出：

| 查詢類型 | 第一次 P95 | 第二次 P95 | 第二次最大 | 限制 |
|---|---|---|---|---|
| 兩詞 AND | 1.6 ms | 1.7 ms | 3.5 ms | P95 ≤ 100 ms |
| 片語 | 48.8 ms | 54.0 ms | 101.2 ms | P95 ≤ 100 ms |
| 最高頻兩詞 AND | 1.9 ms | 2.0 ms | 6.5 ms | P95 ≤ 100 ms |
| 最高頻兩詞片語 | 81.2 ms | **98.0 ms** | 162.4 ms | P95 ≤ 100 ms |

開啟既有索引在第二次為 154 ms。

### 最壞情境的解讀

- 這份語料的高頻詞出現在**每一份**文件中（第 1 到第 25 高的 df 都是 50,000）。這兩個詞組成的片語，必須解碼兩個詞在全部 50,000 份文件中的位置，才能算出精確的 tf 與總命中數。這就是片語查詢在這份語料上的上限。
- 最壞情境的片語 P95 在兩次量測中分別是 81.2 ms 與 98.0 ms，**都符合 ≤ 100 ms 的限制，但餘裕很小**。在較慢的 8 核心機器上可能超過。
- 兩詞 AND 不受影響：它只需要合併 postings，不需要解碼位置，最壞情境的 P95 也只有 2 ms。
- 隨機抽詞的查詢集中，查詢用詞的 df 中位數是 60.4%，第 95 百分位是 100%。也就是說，隨機查詢集本來就包含一部分最高頻詞，但沒有刻意集中在最壞的情況。

### 語料的變更

- 這一版的 `CorpusGen` 只使用 Big5 第一級常用字。原因是 LocalSeek 現在會把「常用字比例過低」的 Big5 檔案視為疑似簡體 GBK 並跳過，而舊版語料是從所有 Big5 漢字中平均抽字，常用字只占約 40%，會被誤擋。
- 抽字範圍仍是 3,500 個字，只是改從常用字中抽取。與舊語料相比，建立索引時間較長（135 s；舊語料兩次為 109 s 與 117 s），片語 P95 也略高（48.8 ms 與 54.0 ms；舊語料為 43 ms 與 51 ms）。這些差距與同一份語料兩次量測之間的起伏同一個量級，原因沒有進一步分析。
