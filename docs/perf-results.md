### 最壞情境與片語平行化

- 這份語料的高頻詞出現在**每一份**文件中（第 1 到第 25 高的 df 都是 50,000）。由它們組成的片語，必須解碼兩個詞在全部 50,000 份文件中的位置，再逐份比對起始位置，這是片語查詢最慢的情況。
- 片語原本是單執行緒執行。在同一份語料上，最壞情境的片語 P95 為 81.2 ms 與 98.0 ms，單一查詢最慢 162 ms，雖然符合 ≤ 100 ms，但餘裕很小。
- 分析其中 4 條最壞情境片語：每條平均 36.9 ms，其中 54% 花在解碼位置、44% 花在比對起始位置。這兩步都可以平行處理，而且不需要改索引格式：
  - 每個詞的位置是各自獨立的一串資料。
  - 每份文件的比對只寫入自己的 tf。
- 改為「不同的詞平行解碼，文件依 4,096 份一段平行比對」之後，同樣 4 條片語平均降到 17.9 ms；300 條最壞情境片語的 P95 降到 49.6 ms 與 54.2 ms，最慢 71.5 ms。
- 兩詞 AND 不需要解碼位置，原本就很快，不受影響。

| 最壞情境片語 | 平行化前 | 平行化後 |
|---|---|---|
| P95（兩次量測） | 81.2 ms / 98.0 ms | 49.6 ms / 54.2 ms |
| 最慢單一查詢（兩次量測） | 141.6 ms / 162.4 ms | 71.5 ms / 65.0 ms |
| 隨機片語 P95（兩次量測） | 48.8 ms / 54.0 ms | 30.7 ms / 34.4 ms |

### 隨機查詢集的代表性

- 隨機查詢從實際文件的文字中抽詞，每次重建索引後抽到的詞不同。
- 這次查詢用詞的 df 中位數是 N 的 78.0%（上一次重建是 60.4%），第 95 百分位是 100%。
- 所以隨機查詢集本來就包含一部分最高頻詞；最壞情境查詢則把全部查詢集中在最高頻詞上。

### 語料的變更

- 這一版的 `CorpusGen` 只使用 Big5 第一級常用字。原因是 LocalSeek 現在會把常用字比例過低的 Big5 檔案視為疑似簡體 GBK 並跳過；舊版語料從所有 Big5 漢字中平均抽字，常用字只占約 40%，會被誤擋。
- 抽字範圍仍是 3,500 個字，只是改從常用字中抽取。
